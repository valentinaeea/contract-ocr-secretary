# 合同智能识别系统 · 秘书端 v1

本仓库为「合同识别系统秘书端」，当前版本 v1，使用 main 作为主分支。基于 Claudia 原版源码，原本地源码保持不变。删除设置页面和导航；保留原有业务 UI、OCR、合同检索、合同编辑/Tag、Excel 导入导出、云盘合并与共享总表检索。

GitHub Actions 原流程完整保留于 `docs/ci-workflows/`，当前未启用。当前上传凭据无 workflow 权限；未来需要自动构建时由仓库所有者将这些模板放回 `.github/workflows/`。本地 Windows 打包脚本保留原样。

## v1 内置云盘路径

网页不再显示路径输入框。修改 `native/secretary_config.py` 第 4 行 `CLOUD_EXCEL_PATH`，保存并重启即可。可填写同步文件夹或完整 .xlsx 路径；填写文件夹时总表名称为「合同识别总表.xlsx」。原合并、备份、自定义列保留逻辑不变。

当前沿用原源码的企业 UNC 测试地址，未擅自填写未知 OneDrive 地址。Mac 请改成实际同步或已挂载的本机目录；不同电脑的本地 OneDrive 路径可能不同。部署/临时测试可用环境变量 `CONTRACT_OCR_CLOUD_DEFAULT` 覆盖；旧网页保存路径不再生效，网页路径修改 API 已禁用。

本输入源码没有登录模块或独立 Share 授权接口；本版不新增或宣称跨电脑统一身份认证。共享沿用原 Excel 总表机制。真实 OneDrive 同步和 Windows EXE 尚未验证。

Git 分支不包含大体积模型和虚拟环境；本地 ZIP 已包含公共模型。若从 Git 获取源码，请按原 native/fetch_ocr_models.py 与 native/fetch_semantic_model.py 准备模型。

## 在当前 Mac 打开

1. 双击本目录 **start-mac.command**，或双击 **启动.command**。
2. 本机独立依赖已安装，脚本会自动选择空闲端口并打开浏览器；不需要手动填写端口。
3. 使用期间保持启动终端开启；按 Ctrl+C 停止服务。
4. 不要直接双击 index.html。虽然原浏览器备用代码保留，本地 Python 服务才能完整运行原生 OCR、Excel 与云盘总表功能。

新 Mac 第一次运行需要 Python 3.11（python.org）；启动脚本会自动准备 `.venv` 和运行依赖，首次安装需要联网。也可先双击 install-mac.command。原有 OCR/语义模型已包含，不需要重新下载或量化。
如果脚本失去执行权限，在终端运行 `chmod +x start-mac.command install-mac.command`；如果出现 Operation not permitted，请允许终端访问该文件夹后重试。
本 ZIP 不包含本机 `.venv`，也不能将 Mac `.venv` 用于 Windows。Windows 原启动/打包脚本保持原样，本阶段未在 Windows 验证。

## v2.14.6 减少每页工作量、显示耗时构成

- 日期复核：先用 PP-OCRv5 mobile（约 0.2 秒）与 v4 比对，只有两者不一致时才调用较慢的 PP-OCRv5 server（约 2.4 秒）裁决；印刷日期通常一致，不再付出 server 的时间。
- 局部高清补识别只针对小字和低置信行；日期由三模型复核负责，金额误读由文字修正负责。
- 识别卡片显示耗时构成：主识别 / 局部补识别 / 日期复核 所占比例，便于判断慢在哪一步。
- 实测（测试机，合成 A4 页）：主识别约 4.9 秒/页，其中文字识别约 4.1 秒、版面检测约 0.7 秒；ONNX 内存池、批大小、线程自旋等设置无明显改善，更大的批反而更慢。

## v2.14.5 手写日期三模型复核

- 实测：手写“2025年11月19日”被 PP-OCRv4 读成“2025年11月1日日”，置信度却高达 0.993，按置信度筛选无法发现。
- 均衡、精细模式下，扫描页上**每个日期**都单独裁出，由 PP-OCRv5 server 与 PP-OCRv5 mobile 再读一次，与 v4 三方投票：多数结果与 v4 不同则采用多数结果，并把原读法保留为黄色“其他识别”；三方不一致或读不出合法日期时标黄提示人工核对。PDF 文字层（非扫描）的日期不处理。
- 每个日期约 1–2 秒（每页最多 8 个）；没有日期的页面不增加时间。快速模式不复核。
- 局限：手写数字与印刷笔画粘连时（如“月”字末笔与手写“1”连在一起），三个模型可能一致读错，仍需对照原件。

## v2.14.4 速度诊断信息

- 识别卡片显示：页数、平均每页秒数、实际使用的进程数/设定进程数、每进程线程数（如“OCR 99.0 秒 · 15 页 · 平均 6.6 秒/页 · 2/2 个进程 × 2 线程”），便于判断慢在哪里。

## v2.14.3 修复丢字（广州→州、10月→10）、S0C2、排版重叠

- **丢字原因**：v2.14 均衡模式使用的 PP-OCRv5 mobile 识别模型在扫描件上会漏掉常用字（月 日 行 工 用 金 至 广 子），“2026年11月至2026年12月31日”被读成“2026年112026年1231”。在 8 组模拟扫描件上实测：PP-OCRv4 只有全角/半角标点差异；v5 mobile 漏字；v5 server 全对但每行约 2 秒。
- 现在整页识别全部使用 PP-OCRv4（快速、均衡、精细）；不再使用 v5 mobile。
- 精细模式：每页最多 6 行**置信度低于 0.95** 的日期、金额、编号（SOC2/ISO 等）或低于 0.8 的内容用 PP-OCRv5 server 复核，适合手写签字页；印刷清楚的行不复核。均衡模式不复核（实测每页 +10 秒且印刷件无改进）。
- 实测（2 核测试机，合成 A4 扫描页，含局部补识别）：快速 3.8 秒/页、均衡 6.1 秒/页、精细 9.4 秒/页（每复核一行约 2–6 秒）；15 页双进程：快速 61 秒、均衡 99 秒、精细 159 秒。
- 字母数字混淆修正（仅 OCR 文字）：英文词中的 0→O（S0C2→SOC2、IS0→ISO、C0BIT→COBIT），数字中的 O/l→0/1（18O,000→180,000、Page 1l→Page 11），180.000.00→180,000.00，数字间全角冒号/逗号改半角。V50、W70、B8650 等型号不受影响。
- Word/WPS 导出 PDF 的文字层：康熙部首等字符（⽉⽇⼯⾏⽤⼴…）转换为正常汉字，和浏览器版一致。
- 局部高清补识别不再把同一行的不同切分重复叠加到页面上；只有同一位置读法不同（如 USD 100 / USD 1000）才标黄并列。
- 按页排版：同一页正文统一字号（±20%），标题保留较大字号，不再忽大忽小。
- 已识别的合同请删除后重新上传（新旧识别结果不会混用缓存）。

## v2.14.2 修复 v2.14 识别极慢（每份约 2 小时）

- 原因：PP-OCRv5 server 识别模型在 CPU 上整页需约 260 秒（mobile 约 5 秒），v2.14.0/2.14.1 在“均衡”模式的日期金额复核、无文字重试中也调用了它，导致 15 页文件约 2 小时。
- 现在整页识别只用 PP-OCRv4 mobile（快速）或 PP-OCRv5 mobile（均衡、精细）；均衡模式完全不调用 server 模型。
- 精细模式：每页最多 4 行日期、金额或低置信内容，单独裁出该行交给 PP-OCRv5 server 复核（每行约 2 秒）。明显更可信的不同读法采用为正文，另一读法保留为黄色“其他识别”，不静默替换。
- 实测（合成 A4 页，2 线程）：快速约 3.7 秒/页，均衡约 5 秒/页；双进程时多页文件约减半。

## v2.14.1 交付物、排版与浏览器版提示

- **交付物提取修正**：以前只取全文第一个“成果”后面的一行，常抓到违约/解除条款（如“乙方被吊销营业执照…”）。现在收集全部候选，排除违约、解除、赔偿、保密、知识产权等条款语境，优先“交付物/交付成果”标题和“报告、清单、方案”等成果；安永模板优先从附录一工作说明书提取；没有可信候选时留空，不再乱填。已有合同可点“重新分析（无需 OCR）”更新（人工编辑过字段的记录不覆盖）。
- **编辑全文后保留版式**：以前只要增删行或同时改表格多格，保存后就退回纯文本、按原始换行显示。现在逐字对齐修改到原文字框：改字留在原位置，新增的行在原文字框下方展开并顺推后文，按页排版不变。

- **浏览器备用版也保存文字坐标**，可按页排版；卡片标明“浏览器备用版 OCR”，上传时提示改用 ContractOCR.exe。浏览器版仍为单线程，不含多进程提速与 PP-OCRv5。

## v2.14.0 手写日期与识别精度：升级 PP-OCRv5

- **识别模型升级**：以前所有模式都用 PP-OCRv4 mobile，它对手写体很弱。现在：
  - 快速：仍为 PP-OCRv4 mobile（最快，适合清晰印刷件）。
  - 均衡（默认）：PP-OCRv5 mobile 检测 + 识别。
  - 精细：PP-OCRv5 mobile 检测 + **PP-OCRv5 server 识别**，手写日期、签字页优先用这一档。
  PaddleOCR 官方评测中，手写中文行准确率约为：v4 mobile 0.30、v5 mobile 0.42、v5 server 0.58；手写英文/数字 0.26 → 0.58（server）。仍不是 100%，手写内容必须核对原件。
- **日期、金额优先复核**：扫描页中带“年/月/日、日期、签署、金额、人民币、千分位数字”的行，只要不是高置信（<0.9），会优先进入局部高分辨率复核（均衡每页最多 2 处、精细 4 处），用 v5 server 模型重读。结果不同时保留原文并在“不同识别结果”中并列显示，不静默改写数字。
- **不再丢弃低置信文字**：以前置信度低于 0.3 的整行会被直接丢掉，潦草手写日期常在此列；现在阈值降到 0.15，保留并以黄色标记“需核对”。
- 合同详情显示本次使用的识别模型。OCR 缓存与断点按模型区分，旧 v4 结果不会被当作 v5 结果复用；已有合同不受影响，如需用新模型识别，请重新上传或“重新识别”。
- 模型在 Actions 构建时通过 RapidOCR 3.8.4 从其官方仓库下载并按其登记的 SHA256 校验，随 EXE 打包（安装包约增加 100MB）；构建时用合成印刷日期检查模型与字典匹配。运行时不联网、不下载。
- 速度：均衡模式比 v4 慢约 30%，精细（server）约慢 2–3 倍；快速模式不变。

## v2.13.2 识别提速与耗时分开显示

- **单份 PDF 按页分配给全部 OCR 进程**：以前一份文件只在一个进程内逐页识别，另一个进程空闲；现在同一份文件的多页同时识别（每份最多同时处理“进程数”页，两份文件同时上传时仍公平分享）。多页扫描件在 2 进程下理论上接近减半，实际取决于 CPU 和内存。断点、失败页重试、取消和识别结果均与逐页方式一致。
- **进度轮询不再读取全部历史**：以前每 0.8 秒查询进度时都会读取并解析所有任务文件，而每个已完成任务都保存了一份完整 OCR 结果副本；合同越多越慢，并与 OCR 抢 CPU。现在只读取当前任务，识别结果只保存在合同记录中；启动时自动去掉旧任务文件中的重复副本（合同数据不变）。合同查找、保存、分析回写也改为按 ID 读取单个文件。
- 页面图像直接以像素数组交给 OCR，不再逐块编码/解码 PPM（像素完全一致）。
- 语义分析进程降为低优先级，后台分析不再拖慢下一份文件的识别。
- CPU 线程按进程数分配：8 线程及以下 CPU 保持原设置，更多核心的电脑每个进程最多 4 线程；自动模式在 12 线程以上 CPU 且可用内存 ≥6GB 时使用 3 个进程。设置中新增 3、4 个进程选项（重启 EXE 生效）。
- 识别卡片分开显示“OCR 耗时 / 排队时间”和“规则分析、语义分析耗时”，不再把排队时间算入识别时间。
- 未改变识别模式、分辨率、小字补识别和模型；识别结果与 v2.13.1 相同。浏览器备用版（直接打开 index.html）仍为单线程 WASM，速度明显慢于 EXE 原生版。

## Windows 下载即用

到 [Releases](https://github.com/ClaudiaYee/contract-ocr-local/releases/tag/desktop-latest) 下载 **ContractOCR-Windows-x64.zip**，完整解压后双击 **ContractOCR.exe**。模型已随程序打包，运行时不需要安装 Python、下载模型或使用云端 OCR。适用于 Windows 10/11 x64；无需 GPU。

**Code → Download ZIP 是源码和浏览器备用版，不等于 Windows 原生程序。** 双击 index.html 或“启动.bat”仍会使用浏览器 OCR，不能获得原生版的后台任务和进程并行能力。网页顶部显示 v2.12.0，并标明“本机原生 OCR”或“浏览器 OCR”。若 Release 暂无 ZIP，请查看 Actions 的 Windows 构建是否完成。

升级前在旧版“设置”导出 JSON，再在新版导入。旧版浏览器数据不会自动变为新程序的文件数据。

## 取消与移除任务

每个未完成任务右侧有“取消并移除”，上传页顶部有“取消全部未完成”。取消排队任务会阻止它被识别；正在处理的任务会在当前计算结束后的安全位置停止，期间显示“取消中”。取消后自动移除任务卡片，不保存新的合同结果，也不删除已识别的合同。失败的任务卡片可以点击“移除”。

本机后台取消已在服务端完成，关闭网页后也不会恢复该任务。浏览器备用版支持在页/模型调用之间停止，主线程执行中的一次计算无法即时中断。旧版页面里已经运行的任务不会被新版按钮接管；升级前请导出已完成结果，再关闭旧页面停止旧队列。

## 文件、存储与后台运行

- 可一次多选 PDF / 图片，也可在识别时继续添加。原生版将整份文档提交到本机队列，以两个独立进程处理。队列最多20份，单文件上限128MB；不会将文件发到外部服务。
- 原生版的数据保存在 **ContractOCR.exe 旁的 ContractOCR_Data 文件夹**，其中 contracts、jobs、config 子文件夹分别保存合同文字与人工修正、任务记录、配置；采用原子写入的 JSON 文件，任务与合同分别保存。旧版 state.sqlite3 会自动导入一次，并保留为升级备份，不再写入。界面左下角显示完整路径。上传文件在 queue 临时排队，成功完成后原件另存于 sources，queue 中的临时副本删除；用户原文件不变。
- 提交完成后，切换标签页、切换软件乃至关闭网页，后台任务均由本机程序继续执行；重新打开同一个本机地址可恢复任务与已完成记录。保持程序开启可持续处理；新版任务中断后，重新启动同一数据目录的EXE会尝试复用已完成页继续。旧版未保存的断点无法补回。
- 浏览器备用版仍使用浏览器的 IndexedDB，通常位于系统盘的浏览器资料目录，不在解压文件夹中；后台标签页可能被浏览器降速或休眠，关闭页面会中断任务。
- 备份可导出 JSON；要复制整个 ContractOCR_Data 文件夹，请先关闭程序，确保文件写入已结束。不要把含数据的文件夹提交到 GitHub。

## 业务内容归类与审计要点

不只统计字面命中。合同详情与“关键字分析”页新增业务内容归类及原文依据，包括：

| 业务 | 示例表达与边界 |
|---|---|
| IPO相关背景 / 上市支持 | 首次公开发行、首发上市、赴港上市、上市申报、拟在香港交易所上市。仅出现上市背景不代表受托服务是财报审计。 |
| SOC 1 / SOC 2及报告类型 | 分别识别SOC家族及Type I/II、类型一/类型二，兼容S0C等OCR形式。不能把SOC2当SOC1，未明确类型时不补成Type2。 |
| 服务机构财务报告控制鉴证 | 组合识别服务机构、财务报告内部控制及鉴证目标；仅为SOC1相关候选，必须核对适用准则和报告名称。SSAE18单独出现不作SOC1判断。 |
| 数据核查 / 数据质量与业财核对 | 数据核验、业财一致性、订单与账单比对、跨系统准确完整性检查等；纯粹数据保密义务不等于数据核查服务。 |
| ITGC、ITAC与ISO认证准备 | 按控制内容或评估辅导目标提供候选，不将认证准备解释为保证通过认证。 |

**原生版组合使用同义规则和公开预训练的中文语义模型（BGE-small-zh-v1.5量化版）**，可以按业务描述相似性召回部分没有出现字面关键词的条款；浏览器备用版只提供同义及组合规则。语义相似候选不等于最终业务分类或审计结论，仍可能漏检、误检；SOC报告类型、否定语句及具体服务范围必须核对原文。 业务标签可以重叠；以“候选”标记的归类不等于审计结论。轻量分类试验未达标的模型没有启用。当前语义模型是公开预训练模型的本地推理，未用客户合同训练或微调。旧版导入记录可在详情点击“重新分析业务含义”，修正全文后也会重新匹配。

SOC家族边界参考 [AICPA SOC 1说明](https://www.aicpa-cima.com/topic/audit-assurance/audit-and-assurance-greater-than-soc-1)及[AICPA SOC服务](https://www.aicpa-cima.com/resources/landing/system-and-organization-controls-soc-suite-of-services/)。

## 识别质量与速度

原生版采用 RapidOCR / PP-OCRv4 本机 CPU 推理。支持快速、均衡、精细三档；长文档、图像分辨率和CPU会影响耗时。两个进程并发不是无限线程；8GB电脑增加更多任务同时推理未必更快。

低分文字行和未识别到文字的页会提示复核。保留直接编辑全文、保存后重新统计关键字、审计目的与条款依据、CSV（Excel）导出等功能。**OCR不能保证100%准确；金额、日期、主体和关键条款应核对原件。** 字段提取比例不等于OCR字符准确率。

语义模型在Actions构建时从[公开模型仓库](https://huggingface.co/Xenova/bge-small-zh-v1.5)按固定版本下载并核验SHA-256，随Windows程序打包；运行时不访问模型网站、不下载资源。该模型的源模型为[BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)。相似度是语句向量的比较结果，不是准确率。

本机服务只监听127.0.0.1:18765；OCR和写入接口需页面随机令牌及同源请求。ONNX Runtime遥测关闭。应用与安装包不含任何客户测试合同、标注或私有试验模型；公开预训练的语义模型权重与这些私有材料不同，安装包仅包含前者。这些材料不应上传公共仓库或用于其他人的训练。
